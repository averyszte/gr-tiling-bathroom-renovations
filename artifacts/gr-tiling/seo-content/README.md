# GR Tiling — SEO Content Report

Deep, unique, drop-in page copy for the 10 service/info pages that are failing to
index. Generated to fix the root cause: near-duplicate sibling pages, thin unique
body copy, hidden (uncrawlable) FAQ answers, and an identical 3-review block on
every page.

**This folder is a content report, not applied code.** Each `.md` file is drop-in
copy mapped to the existing page component slots (hero, area cards, prose sections,
process, FAQ, CTA, meta, schema). Implementation is a separate step — see
`HANDOFF-PROMPT.md`.

## Why the pages were not indexing (diagnosis)

The stack is fine — prerendering (`scripts/prerender.tsx`), edge meta injection
(`functions/_middleware.js`), sitemap and robots are all correctly set up. This was
never a framework problem. The causes were:

1. **Overlapping sibling pages.** `floor-wall-tiling`, `bathroom-tiling` and
   `kitchen-tiling` all covered the same ground; Google indexed one and treated the
   rest as duplicates ("Crawled/Discovered — currently not indexed").
2. **Identical reviews on every page.** The same three testimonials appeared verbatim
   site-wide, a repeated boilerplate block that diluted each page's uniqueness.
3. **FAQ answers hidden from crawlers.** Answers live in a Radix `<Accordion>` that
   does not mount closed content, so the answers were absent from the prerendered
   HTML — the richest unique copy on each page was invisible to Googlebot.
4. **Thin unique body copy.** After stripping shared hero/reviews/process, each page
   had ~150–200 unique words.

## What this content fixes

- Each page now has 900–1,500 words of genuinely expert, Dublin-specific copy
  (cost-guide 2,000+). Grounded in real housing-stock, substrate, waterproofing and
  grout detail — see `_research-dublin.md`.
- A differentiation architecture assigns every page one focus keyword and an explicit
  "owns / defers" topic split, with a hub-and-spoke internal-link matrix — see
  `_strategy.md`. The floor-wall / bathroom / kitchen overlap is resolved;
  `tiling-services` is the pillar hub.
- 6–8 unique, substantial FAQ answers per page (these must be made crawlable — see
  handoff).
- One topically-matched real review per page instead of the shared block.

## Before publishing — human checks

- **No prices anywhere (client instruction).** Gerry does not want figures shown, so
  the cost-guide was written as a factors-only "what shapes your quote" page — no euro
  amounts, per-m² rates, cost percentages or VAT figures. If any price sneaks back in
  during implementation, strip it.
- **Collect more real Google reviews** (see review strategy in `_strategy.md`):
  ask for reviews naming the specific job — wet room, splashback, regrout,
  accessible/grant work — so future reviews map 1:1 onto pages and cut the forced
  repetition of the three existing quotes. No reviews were invented.
